# BSD App Skill 1.1 — คู่มือครู

ชุดคำแนะนำให้ AI ของ BSD Online สร้างแอปที่ทำงานได้จริงตาม "เกณฑ์ผ่าน" โดยทุกเกณฑ์กลายเป็นการทดสอบอัตโนมัติที่ผู้เรียนกดดูผลเองได้

สถานะ: เนื้อหาและแอปตัวอย่างตรวจแล้วใน Edge / ยังไม่ได้ทดลองบน BSD Online จริง (ดู "ก่อนใช้ใน workshop")

## แนวคิดหลัก (อธิบายผู้เรียนใน 5 นาที)

1. **เกณฑ์ผ่านก่อนโค้ด**: ทุกคำขอมี `AC1, AC2, …` แบบ "เมื่อ … แล้ว …" ที่วัดได้
2. **ทุกเกณฑ์ = การทดสอบที่กดจริง**: ปุ่ม "ทดสอบ" ในแอปจะกรอกช่องและกดปุ่มแทนผู้ใช้ แล้วบอก ✓/✗ ทีละข้อ AI ไม่ได้รันโค้ด จึงห้ามอ้างว่า "ผ่าน" ผู้เรียนเป็นคนกดยืนยัน
3. **แอปรายงาน error เอง**: AI มองไม่เห็น Console ของผู้เรียน แอปจึงมีกล่องแดงพร้อมปุ่ม "คัดลอกรายงานบั๊ก" (มีข้อความ error, ไฟล์:บรรทัด, การกระทำล่าสุด) วางในแชทได้ทันที
4. **โครงสร้างแบบ production ไม่ต้องใช้ .env**: CONFIG (ค่าที่ไม่ลับ) → DB (หลังบ้านในเบราว์เซอร์: ตรวจข้อมูล กฎธุรกิจ เก็บถาวร) → API (timeout, cache, ข้อความผิดพลาด) → UI → EVENTS → TESTS

## ตอบคำถามที่พบบ่อย

**ใช้ API ภายนอก เช่น สภาพอากาศ หรือ PM2.5 ได้ไหม**
ได้ เมื่อ (1) ไม่ต้องใช้ key ลับ เพราะโค้ดหน้าเว็บทุกคนเปิดดูได้ และ (2) API อนุญาตให้เรียกจากเบราว์เซอร์ (CORS) ผลตรวจจริงวันที่ 18 พ.ย. 2026: Open-Meteo สภาพอากาศและ PM2.5 เรียกได้ ไม่ต้องใช้ key ส่วน Air4Thai ของกรมควบคุมมลพิษมีข้อมูลแต่ไม่อนุญาต CORS จึงเรียกตรงจากหน้าเว็บไม่ได้ ต้องมี server กลาง แอปตัวอย่างใช้ Open-Meteo จริง

**ใช้ CDN เช่น React ได้ไหม และทำไมค่าเริ่มต้นคือไม่ใช้**
ใช้ได้เมื่อผู้เรียนขอและระบุเวอร์ชันตายตัว เหตุผลที่ค่าเริ่มต้นไม่ใช้:
- ถ้า CDN โหลดไม่ได้ แอปพังทั้งหน้า
- AI มักผสมเวอร์ชันหรือเขียน JSX ที่ต้องคอมไพล์ ซึ่งแพลตฟอร์มไม่มี build
- error จากไฟล์ CDN มักขึ้นแค่ "Script error." ทำให้แก้บั๊กยาก

สำหรับ workshop ที่เวลาจำกัด JavaScript ธรรมดาเสถียรที่สุด ถ้าต้องใช้กราฟ ไลบรารีเล็กอย่าง chart.js แบบระบุเวอร์ชันพอรับได้

**Skill ทำให้ AI แก้บั๊กเก่งขึ้นจริงไหม**
Skill ไม่ได้ทำให้โมเดลฉลาดขึ้น แต่แก้สาเหตุหลักที่ทำให้แก้บั๊กไม่ได้ คือ AI ไม่มีหลักฐาน Skill บังคับให้แอปส่งหลักฐานที่แม่นยำ (ข้อความ error + บรรทัด + ขั้นตอน หรือ AC ที่ล้ม) และบังคับขั้นตอน: อ่านบรรทัดนั้น หาสาเหตุแรก แก้จุดเดียว เพิ่มการทดสอบ หยุดถ้า 2 ครั้งไม่หาย
ตัวอย่างที่พบจริงใน IDE: AI เขียน `steps:.querySelectorAll` (ตกคำ `document`) ตัวจับ error ของ Skill แสดง `SyntaxError: Unexpected token '.' (script.js:71:21)` ให้คัดลอกส่ง `/skill fix` ได้ทันที (ตรวจแล้วใน Edge)

| นาที | กิจกรรม |

| 0–10 | สาธิต `example/`: กดทดสอบ (ผ่าน 7/7), ดูหน้าอากาศ, ทำให้พังแล้วดูรายงานบั๊ก |

| 55–75 | `/skill add` 1 ฟีเจอร์พร้อม AC ใหม่ → ทดสอบอีกครั้ง (ของเดิมต้องยังผ่าน) |
| 75–85 | `/skill test` + `/skill check` ก่อนส่งงาน |
| 85–90 | สรุป: AI เขียน / การทดสอบยืนยัน / คนตรวจข้อ [คนตรวจ] |

## ก่อนใช้ใน workshop (ครูทดลอง 1 รอบ)
1. ลอง prompt ขั้นที่ 0 ว่า AI ดึงจาก URL และสร้างไฟล์ได้ครบถึงบรรทัด "— จบ SKILL.md v1.1.0 —" (ไม่ได้ ลอง URL สำรอง แล้วจึงใช้แบบวางเนื้อหา)
2. แชทใหม่ พิมพ์ `/skill` ว่า AI ยังอ่าน SKILL.md ในโปรเจกต์ได้
3. ลองตัวอย่าง "อิ่มไว" ใน PROMPTS.md กดทดสอบ จดจำนวนที่ผ่านครั้งแรกและเวลาที่ใช้
4. ลองเรียก Open-Meteo จาก Preview ของแพลตฟอร์ม (บางแพลตฟอร์มบล็อกการเชื่อมต่อภายนอกใน Preview)

## ข้อจำกัดที่ควรบอกผู้เรียน
- ข้อมูลเก็บในเบราว์เซอร์เครื่องนั้นเท่านั้น
- การทดสอบตรวจพฤติกรรมตามเกณฑ์ ไม่ตัดสินความสวย (ข้อ [คนตรวจ])
- การทดสอบที่ AI เขียนอาจผิดได้เอง (เช่น นับรายการเกิน) ถ้าข้อไหนล้มทั้งที่แอปดูถูก ให้ `/skill fix` พร้อมเหตุผลที่ล้ม AI ต้องอธิบายก่อนแก้การทดสอบ
