# app-check — เกณฑ์ผ่านที่วัดได้ และการทดสอบที่กดจริง

ดัดแปลงจาก skill testing-and-verification และ requirements-and-acceptance ของ IDE

## กฎ
- เกณฑ์ผ่านทุกข้อมีเลข `ACn` และการทดสอบ `test('ACn', …)` อย่างน้อยหนึ่งข้อ
- การทดสอบกดปุ่ม/กรอกช่องจริงด้วย `ui.*` แล้วตรวจสิ่งที่ผู้ใช้เห็น ไม่ใช่เรียกแค่ฟังก์ชันข้อมูล
- AI ไม่ได้รันโค้ด ห้ามบอกว่า "ผ่านแล้ว" ให้บอก "เขียนการทดสอบแล้ว รอผู้ใช้กดทดสอบ"
- ผลที่นับว่าผ่าน = ผู้ใช้กด "ทดสอบ" แล้วได้ ✓ ครบ

## เขียนเกณฑ์ให้วัดได้
รูปแบบ: `ACn: เมื่อ <ทำอะไร> แล้ว <เห็น/ได้อะไรที่นับหรืออ่านค่าได้>`

| คลุมเครือ | วัดได้ |
|---|---|
| ตะกร้าทำงาน | AC3: เมื่อเพิ่มข้าวผัด 60 บาท 2 จาน แล้วยอดอาหาร 120 และยอดรวม 145 (ค่าส่ง 25) |
| ค้นหาได้ | AC4: เมื่อพิมพ์ "ส้มตำ" แล้วเห็นเฉพาะร้านที่มีส้มตำ และพิมพ์ "zzz" แล้วเห็น "ไม่พบร้าน" |
| ฟอร์มตรวจข้อมูล | AC5: เมื่อเว้นเบอร์โทรแล้วกดยืนยัน แล้วเห็น "กรอกเบอร์โทร" ใต้ช่อง และชื่อที่กรอกไม่หาย |
| จองไม่ได้ย้อนหลัง | AC6: เมื่อเลือกวันที่เมื่อวาน แล้วกดจองไม่ได้และเห็นเหตุผล |
| ข้อมูลไม่หาย | AC7: เมื่อรีเฟรช (DB.reload) แล้วตะกร้ายังมี 2 รายการ |
| สวยงาม | [คนตรวจ] เปิดบนมือถือ ข้อความอ่านง่าย ไม่มีส่วนล้นจอ |

ต้องมีเสมอ (ถ้าแอปมีเรื่องนั้น): งานหลักสำเร็จ, ข้อมูลผิดถูกปฏิเสธพร้อมคำแนะนำ, ข้อมูลอยู่หลังรีเฟรช, หน้าว่าง/ไม่พบ, ตัวเลขคำนวณถูก, การยืนยันก่อนลบ, ข้อมูลภายนอกล้มเหลวแล้วมีทางไปต่อ

## รูปแบบการทดสอบที่ใช้บ่อย

```js
// ตัวเลขคำนวณ
test('AC3', 'ยอดรวม = อาหาร + ค่าส่ง', async () => {
  ui.click('[data-action="add"][data-menu="1"]'); ui.click('[data-action="add"][data-menu="1"]');
  ui.go('#cart');
  await ui.until(() => ui.text('#food-total') === '120', 'ยอดอาหารไม่ใช่ 120');
  expect(ui.text('#grand-total') === '145', 'ยอดรวมไม่ใช่ 145');
});
// กฎธุรกิจที่ต้องถามก่อน (confirm): แทนการยืนยันชั่วคราวในการทดสอบ
test('AC8', 'เปลี่ยนร้านแล้วถามก่อนล้างตะกร้า', async () => {
  let asked = false; window.confirmClear = () => { asked = true; return false; };
  /* เพิ่มเมนูร้าน A แล้วเพิ่มเมนูร้าน B */ expect(asked, 'ไม่ได้ถามก่อนล้าง');
});
// วันที่
test('AC6', 'ห้ามวันที่ย้อนหลัง', async () => {
  const y = new Date(Date.now() - 86400000).toISOString().slice(0, 10);
  ui.fill('#date', y); ui.click('[data-action="book"]');
  await ui.until(() => ui.text('#date-error') !== '', 'ไม่มีข้อความเตือนวันที่');
});
// ข้อมูลเสียใน localStorage
test('AC9', 'ข้อมูลเสียแล้วแอปไม่พัง', () => {
  localStorage.setItem(CONFIG.storageKey, '{broken'); DB.reload(); expect(Array.isArray(DB.list()), 'แอปพังเมื่อข้อมูลเสีย');
});
```

- ปุ่ม confirm/prompt ของเบราว์เซอร์: ให้แอปเรียกผ่านฟังก์ชันที่แทนได้ เช่น `window.confirmClear ? confirmClear() : confirm(...)` เพื่อให้ทดสอบได้
- API ภายนอก: แทน `API.getJSON` ชั่วคราวทั้งกรณีสำเร็จและล้มเหลว
- เวลา/ตัวจับเวลา (เกม): ให้ state มีฟังก์ชัน `tick(ms)` ที่การทดสอบเรียกเองได้ ไม่ต้องรอเวลาจริง
- สุ่ม: รับ seed หรือฟังก์ชันสุ่มที่แทนได้ในการทดสอบ

## selector ที่ดี
- นับรายการด้วย `#list > li` (หนึ่ง element ต่อหนึ่งรายการ)
- ปุ่มด้วย `[data-action="…"]` ช่องด้วย `#id` ข้อความ error ด้วย `#<ช่อง>-error`
- ห้ามหา element จากข้อความบนปุ่ม (ข้อความเปลี่ยนบ่อย)

## เมื่อการทดสอบไม่ผ่าน
อ่านเหตุผลในรายงาน ("รอเกิน 2000ms: ยอดอาหารไม่ใช่ 120") แล้วใช้ `/skill fix` พร้อมผลทดสอบ ห้ามแก้การทดสอบให้ผ่านโดยไม่แก้ต้นเหตุ ถ้าการทดสอบผิดจริง (เช่น selector นับเกิน) ให้บอกเหตุผลก่อนแก้

## ตรวจด้วยคน (ข้อ [คนตรวจ])
1. ย่อจอแบบมือถือ ไม่มีแถบเลื่อนแนวนอน
2. ใช้ Tab เดินผ่านปุ่มและช่องได้ เห็นกรอบโฟกัส
3. อ่านข้อความได้สบาย สีตัดกันชัด
